This page is the single reference for annotations that are built into the XIDL
language. Protocol-specific annotations (HTTP verbs, streams, security, ...)
are documented in their own sections.

## Checking annotations

Run annotation checks explicitly before generating a contract:

```sh
xidlc lint api.idl shared.idl
xidlc lint --deny warnings api.idl
```

`lint` checks built-in names, declaration positions, and argument shapes. It
reports source locations and stable diagnostic codes:

| Code | Level | Example |
| --- | --- | --- |
| `misspelled-annotation` | error | `@remvoed` suggests `@removed` |
| `misplaced-annotation` | error | `@optional` on an interface |
| `bad-annotation-args` | error | `@api_key` without `name` |
| `unknown-annotation` | warning | An external plugin's `@relay_audit` |

Built-in annotation names ignore ASCII case. Target-specific `rust-`, `rust_`,
`ts-`, and `ts_` attributes pass through without validation. Unknown annotations
remain available to plugins; `--deny warnings` only changes the CLI exit policy.

The command checks every supplied file and exits with status 1 for errors,
including unreadable or unparseable files. Warnings alone exit with status 0
unless `--deny warnings` is set. It does not rewrite sources or generate files.
`xidlc gen` does not run lint, so CI should invoke both commands explicitly.

Editor integrations can use `xidl_parser::lint::BUILTIN_ANNOTATIONS` for completion
and `xidl_parser::lint::lint(&typed_ast::Specification)` for the same diagnostics.
The library is a pure function; diagnostic spans are half-open UTF-8 byte ranges
in the parsed source. Type resolution and generator-specific semantic validation
remain separate checks.

## `@rename`

`@rename("...")` is used to rename the serialized name of a field or
parameter.

- Acts on `struct` / `union` members and method parameters.
- Used as the wire / property name when generating HTTP / JSON mappings.
- Typically maps to `#[serde(rename = "...")]` in Rust.

Example:

```idl
struct User {
  uint32 id;
  @rename("new_name")
  string name;
};
```

## `@rename_all`

`@rename_all("...")` renames all fields of a struct, or all parameters of a
method, according to a naming rule.

```idl
@rename_all("snake_case")
struct User {
  uint32 id;
  string name;
};
```

Supported parameters:

- lowercase
- UPPERCASE
- PascalCase
- camelCase
- snake_case
- SCREAMING_SNAKE_CASE
- kebab-case
- SCREAMING-KEBAB-CASE

## `@skip`

`@skip` excludes a struct field from serialization and deserialization:

```idl
struct User {
  uint32 id;
  @skip
  string internal_note;
};
```

## `@optional`

`@optional` marks a field or parameter that may be absent. In HTTP scenarios,
optional query parameters and body fields can be omitted; path parameters
cannot be optional. See the [HTTP RFC](../../rfc/http/) for details.
