A versioned IDL describes **one** contract: the latest state of the API. The
version history is declared next to it, and older versions are derived from
annotations instead of copied files.

```idl
#pragma xidlc package petstore

@version
enum ApiVersions {
    @rename("1.0") v1,
    @rename("2.0") v2,
};

struct Pet {
    string id;

    // introduced in v2
    @added(ApiVersions::v2)
    @optional string note;

    // deprecated at v2 and gone from then on
    @removed(ApiVersions::v2)
    string color;
};

interface Pets {
    @get(path = "/pets/{id}")
    Pet get(@path string id);

    @removed(ApiVersions::v2)
    @get(path = "/legacy")
    string legacy();
};
```

## Lock released versions

Use a version lock file to detect changes to the IDL projection of a released
version. Pass the version's declared value with `--version`. Repeat the option
to provide the complete set you want to lock.

```sh
xidlc version lock --version 1.0 --lock-file pets.lock.json pets.idl
xidlc version check --version 1.0 --lock-file pets.lock.json pets.idl
```

An explicit lock writes only the supplied versions. An explicit check requires
each supplied version to be locked and verifies its fingerprint. Check also
reports any locked version removed from the contract. Without selection, lock
writes every declared version, and check verifies the lock file. Add `--strict`
to an unfiltered check to require a lock for every declared version.

Your application chooses which versions to freeze and can skip lock and check
when its frozen set is empty.
