A versioned IDL describes **one** contract: the latest state of the API. The
version history is declared next to it, and older versions are derived from
annotations instead of copied files.

```idl
#pragma xidlc package petstore

@version
enum ApiVersions {
    @rename("1.0") v1,
    @rename("2.0") v2,
};

struct Pet {
    string id;

    // introduced in v2
    @added(ApiVersions::v2)
    @optional string note;

    // deprecated at v2 and gone from then on
    @removed(ApiVersions::v2)
    string color;
};

interface Pets {
    @get(path = "/pets/{id}")
    Pet get(@path string id);

    @removed(ApiVersions::v2)
    @get(path = "/legacy")
    string legacy();
};
```

## Lock released versions

Use a version lock file to detect changes to the IDL projection of a released
version. Pass the complete set of declared version values as a JSON array with
`--versions`.

```sh
xidlc version lock --versions '["1.0"]' --lock-file pets.lock.json pets.idl
xidlc version check --versions '["1.0"]' --lock-file pets.lock.json pets.idl
```

An explicit lock replaces the entire stored set with the supplied versions.
Use `--versions '[]'` to write an empty lock. An explicit check requires each
selected version to be locked and verifies its fingerprint. Every check reports
locked versions removed from the contract. With no selection, lock writes
every declared version and check verifies every locked version. List all
declared values to require a lock for the whole contract.
