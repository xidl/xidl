## Imported Units

`#include "file.idl"` copies a file into the current unit, so both files share
one scope and one output. `import` names another **compilation unit**: the
compiler generates that unit on its own and the importing unit refers to its
types.

## Syntax

```idl
import "timestamp";            // imports timestamp/index.idl
import "timestamp/util.idl";   // imports one file of that package
import "timestamp@v1";         // binds the default API version of the unit
```

Paths resolve against the dependency mounts of `xidl.toml` first and against
the importing file's directory afterwards. A directory resolves to the
`index.idl` inside it, so a package is imported by its name. The reference
prefix is the last path segment without its `.idl` suffix: `timestamp` for
`timestamp/index.idl`, `util` for `timestamp/util.idl`.

## Generated output

Every unit is compiled and generated by itself:

- `app.idl` becomes `app.rs`.
- `timestamp/index.idl` becomes `timestamp.rs` and holds every version of the
  unit.

A unit refers to another unit through its prefix and an API version:

```idl
// app.idl
import "timestamp";

struct Event {
    timestamp::v1::Instant at;
};
```

```rust
// app.rs
use crate::timestamp;

pub struct Event {
    pub at: timestamp::v1::Instant,
}
```

The version in the reference selects a module of the imported unit:

```rust
// timestamp.rs
pub mod v1 {
    pub struct Instant { pub at: String }
}
pub mod v2 {
    pub struct Instant { pub at: String, pub monotonic: Option<String> }
}
```

Generating a unit generates every unit it imports, transitively and once each.
A cycle between units is an error, and so is a path that resolves to a
directory without an `index.idl`.

## Include and import side by side

| | `#include "x.idl"` | `import "x"` |
| --- | --- | --- |
| Copies the file text | yes | no |
| Shares one output | yes | no |
| Generated separately | no | yes |
| Reference form | `Pet` | `x::v1::Pet` |
| Version selector | unsupported | binds the default version |

## Current limits

- The Rust target emits the type import that resolves a cross-unit reference.
  Other targets still render the qualified name without an import.
- A version selector binds the default version of a unit. References spell the
  version explicitly for now, as in `timestamp::v1::Instant`.
- A version selector on `#include` is not implemented yet.
